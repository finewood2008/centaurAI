# 知君私人记忆盒子商业计划书

半人马人工智能　2026 年 10 月

> 知君是一只私人记忆盒子。它通过对话逐渐认识你，把这份认识交给你掌管；
> 要独自拿主意时陪你商量，结果回来时陪你复盘。
> 当你愿意，再把亲自确认过的经验，开放给需要它的人。

## 产品定位

知君是一个知己与导师，不是工作助理。

它面向需要独自做重要判断、身边却没有人可以说真话的人。知君在长期对话中形成对本人的理解，即「个人本体」，包括这个人在意什么、怎么做决定、后来对不对。这份理解保存在本人持有的盒子里，由本人确认和修正。

知君分两步走：

- **第一步：知己。** 帮一个人认识自己、做好判断。这是产品的根本，也是首批交付的全部内容。
- **第二步：分身。** 本人可以把逐条确认过的经验和方法，发布成对外的角色，为获得授权的人提供问答与咨询。

两步的信任承诺正好相反：第一步承诺「没有人会看到」，第二步承诺「被授权的人可以问」。知君用一道单向阀门把它们连接起来，具体见「第二步」一节。

## 用户与痛点

首批用户是企业经营者、高管和独立顾问。他们的孤独来自所处的位置，不是性格。

**判断无处商量。** 身边每个人都和这件事有利害关系，员工、合伙人、家人、客户都是。真正的顾虑说不出口，说出口的又不是真话。

**判断没有回路。** 决定做完就过去了。当时为什么这样选、预期是什么、后来对不对，很少有人回头看，同样的错会以新的形式再来一次。

**心里的事没有地方放。** 压力、自我怀疑、对自己的看法，这些对判断影响最大的东西，恰恰最不适合讲给任何利益相关的人。

**经验困在自己身上。** 对其中的顾问和专业人士来说还有第四个痛点：最有价值的判断方法藏在经历里，只能靠本人一次次亲自解释。这是第二步要解决的问题。

## 解决方案

### 通过对话形成个人本体

对话是构建本体的主要方式，资料导入只用来加速。知君把事实、人、经历、原则和判断组织起来，每一条都标明来源：

【你告诉我的】【资料里看到的】【我推测的】【知君的看法】

本人亲口说的事实直接记住，可以随时撤回。知君推测出来的理解，只会带着保留语气在对话中使用，本人确认后才成为本体的一部分。

### 当下商量与判断回访

- **当下商量**：要拿主意时，知君调用本人过去的原则、相似的经历和相关的人，帮本人把顾虑说清楚。知君可以有自己的看法，但看法永远只是看法，不替人做决定。
- **判断回访**：知君记下当时的决定和预期，几周后主动回来问「现在回看怎么样」。判断的回路是知君最核心的循环。

### 内观

本体里有两个只属于本人的分区：「心里的事」和「我眼中的我」。知君会把本人对自己的看法，与实际行为中观察到的模式对照，指出其中的张力，帮人看见自己。

### 有边界的知己

- **把人推回人。** 知君要减少孤独，不是替代人。该和某个人谈的事，它会直说「这件事你该和他谈」。这条原则不可关闭。
- **接住危机。** 遇到危机情境，知君会接住、不追问，提供真实可用的求助渠道，并明确说明自己不是心理治疗。这段对话完全不进入记忆。

## 为什么是盒子

**本地优先不是隐私功能，是袒露心声的前提。** 一个人只有确信内容不会流到别处，才会说真话。

知君软硬件一体交付，个人本体和全部对话都保存在本人拥有的盒子里。盒子是专用设备，不运行别的软件，也不随人移动，比个人电脑更适合承担这份信任。同时保留独立部署版本，供不需要硬件的用户使用。

需要外部模型增强时，由本人选择是否开启，并且清楚看到发送了什么：原件不出设备，云端模型只收到必要的片段，每一次发送都可见、可审计。

## 产品形态

**第一步**

- **私人记忆盒子**：保存个人本体、对话和判断记录。
- **本人客户端**：没有复杂导航，只有一条按天展开的对话。知君每天先开口，可能是一次回访、一个问题，或者一件它注意到的事。

**第二步**

- **角色管理**：本人决定发布哪些经验，开放哪个角色，授权给谁。
- **来访者入口**：获得授权的来访者与开放的角色对话。

## 第二步：从知己到分身

第一步积累了一个人怎么做判断、后来对不对。第二步让本人把其中愿意分享的部分，变成可被提问的专业能力。

### 单向阀门

- 私人积累要经本人**逐条确认**，才能发布给对外角色使用。发布可以随时暂停和撤回。
- 「心里的事」「我眼中的我」、情绪记录和危机对话**永远不能发布**。这不是默认关闭，而是不存在这个开关。
- 角色专属的上下文和来访者的会话分别管理。来访者的会话不会回流到本人的私人积累，除非本人确认。

### 客户之间的保密

顾问最有价值的是跨客户的经验，而这些经验大多受保密约定约束。案例要先脱敏，并经本人确认「可以对外引用」，才能被角色使用。角色回答问题时，不会把一个客户的情况透露给另一个客户。

### 本人接续

角色回答第一层问题：已有的案例、方法和适用条件。涉及具体决策、复杂条件或需要新研究的问题，角色会明确交给本人。这道接续是第二步的主线，也是后续收费咨询的入口。

### 首批场景

| 场景 | 角色负责 | 本人接续 |
|---|---|---|
| 经营与组织顾问 | 调用相关案例，解释分析方法 | 具体决策与复杂条件 |
| 行业研究顾问 | 组织已有研究、经验与适用条件 | 超出范围或需要新研究的问题 |
| 项目复盘顾问 | 串联脱敏后的项目背景、行动与结果 | 核对差异，补充当前判断 |

## 价值闭环

**第一步**：聊 → 记 → 认 → 用 → 回访 → 长

每一次商量都留下一条可以回访的判断；每一次回访，都让知君对这个人的理解更准确。

**第二步**：确认 → 发布 → 授权问答 → 本人接续 → 经确认回流

第一步积累的判断，是第二步分身的质量来源。没有第一步，第二步只是一个读过你文件的问答机器人。

## 差异化

| | 通用 AI 助手与陪伴产品 | Delphi 等数字分身 | 知君 |
|---|---|---|---|
| 目标 | 完成任务，或提高使用时长 | 放大公开影响力 | 帮本人认识自己、做好判断 |
| 素材 | 对话与工作数据 | 公开作品（书、文章、播客、课程） | 长期对话中形成的判断及其结果 |
| 数据在哪 | 平台 | 平台 | 本人的盒子 |
| 对外 | 无 | 默认对外 | 默认私密，逐条确认后经单向阀门发布 |

知君的差异落在「判断」，而不是「内容」。公开作品谁都能读到，一个人怎么做决定、后来对不对，只有长期陪他商量和复盘的知君才拿得到。

我们也清楚自己的劣势：对于第二步的来访者，连接一个盒子比打开一个网页链接麻烦。来访入口的轻量化，是第二步要解决的产品问题。

## 商业模式

| 收入 | 阶段 | 内容 |
|---|---|---|
| 硬件销售 | 第一步 | 私人记忆盒子，软硬件一体交付 |
| 持续订阅 | 第一步起 | 模型增强、资料整理、维护支持 |
| 咨询分成 | 第二步 | 经知君交付与结算的收费咨询 |

定价原则：

- **内容不流经我们。** 订阅、连接与结算服务只处理各自职责所需的信息。
- **停付后仍能打开。** 已有的本体和对话归本人所有，可以查看、导出和迁移，与增值订阅分开设计。
- **对标教练与咨询，不对标工具。** 价值在于判断，不在于功能数量。
- **不按使用频次计价。** 不能让「多聊」成为我们的收入来源。

价格、订阅权益和分成比例将根据首批用户的使用和交付成本确定。本册不使用未经验证的收入预测。

## 验证指标

**北极星：每月形成可以回访的判断的次数。**

我们不用使用时长或对话次数作为核心指标。情绪价值无法在不读取内容的前提下度量，硬套代理指标会诱导产品制造依赖，这和「把人推回人」相冲突。

| 方面 | 要验证的问题 |
|---|---|
| 第一步 | 用户是否愿意说真话；判断回访是否被认为有价值；三个月后是否仍在使用 |
| 第二步 | 发布的内容是否得到本人认可；来访者是否得到帮助、是否再次访问 |
| 经营 | 盒子的交付与服务成本；整机与订阅的付费意愿 |

## 增长路径

通过半人马 AI 学院、经营者社群和顾问社群，邀请首批用户在真实处境中使用。

> 经营者 / 顾问成为主人 → 持续使用第一步 → 顾问发布角色、邀请客户 → 客户中出现新主人

「顾问邀请客户，再产生新的盒子主人」是一个需要通过实际使用验证的增长假设。

## 产品演进

| 阶段 | 内容 |
|---|---|
| 知己 | 个人本体、当下商量、判断回访、内观、边界与危机处理 |
| 分身 | 单向阀门、多角色、案例脱敏、授权访问、本人接续 |
| 商业闭环 | 整机、订阅与收费咨询的权益、交付和结算 |
| 长期上下文 | 接入录音设备，降低记录经历的成本；涉及他人的录音须先解决知情同意 |

以上是演进规划。整机本地运行、多角色、跨网络授权和迁移等能力，以实际版本验收为准。

## 风险与应对

| 风险 | 应对 |
|---|---|
| 情绪安全 | 危机对话不进入记忆；求助渠道上线前逐条核实；负面情绪不作为主动提起的优先依据 |
| 用户依赖 | 「把人推回人」作为不可关闭的原则；北极星不按时长计 |
| 第二步隐私 | 单向阀门；内观分区永不可发布；案例脱敏与本人确认 |
| 推送外泄 | 心里的事不进任何推送；判断回访只在本人标为「私人」的渠道带内容，其他渠道只提醒 |
| 技术上游集中 | 底座与万象共用开源平台，知君只承担判断、照见与边界三层，保持可替换 |
